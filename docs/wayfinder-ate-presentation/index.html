Wayfinder + Agent Technical English

Keeping architectural exploration flexible, decisions human-owned, and execution precise.

NeoBank Digital Leap · Workflow Retrospective · August 2026

The main risk was not missing intelligence

Long-running AI work usually fails through:

  • Hidden decisions
  • Context drift
  • Premature implementation
  • Ambiguous instructions
  • Uncontrolled parallel work
  • Unrecorded human approvals

The problem was coordination under uncertainty.

The two methods solve different problems

Wayfinder finds the route

  • Maps unresolved decisions
  • Exposes dependencies
  • Preserves uncertainty
  • Maintains human authority

Agent Technical English secures each step

  • Reduces semantic freedom
  • Defines scope and authority
  • Makes completion observable
  • Controls side effects

Wayfinder at the decision level. ATE at the execution boundary. Neither replaces human judgment.

The map is a hypothesis, not a backlog

A Wayfinder map contains:

  • Destination — what "done" means
  • Notes — constraints and execution boundaries
  • Decisions so far — accepted conclusions
  • Not yet specified — visible fog
  • Out of scope — deliberate exclusions

The map evolves when evidence changes the route.

One frontier decision at a time

Four ticket types:

  • Grilling — clarify through one material question at a time
  • Research — gather evidence without selecting the outcome
  • Prototype — create cheap alternatives for human comparison
  • Task — complete a prerequisite that exposes facts

Structural independence does not authorize parallel execution.

A recommendation is not a decision

For every material choice:

  • The agent MAY prepare alternatives.
  • The agent MAY recommend one alternative.
  • The human selects, rejects, or defers.
  • Generic "continue" does not approve an unnamed option.
  • The ticket closes only after an explicit decision.
DECISION OWNER: HUMAN

Each answer reshapes the remaining route

After every decision:

  1. Record the approved answer.
  2. Update the map.
  3. Re-evaluate dependent tickets.
  4. Remove obsolete questions.
  5. Promote newly precise uncertainty.
  6. Recommend one next frontier.

Fog becomes work only when the question is precise.

Controlled language begins at execution

Use normal language for

  • Exploration
  • Discussion
  • Comparison
  • Architectural reasoning

Use ATE for

  • Agent handoffs
  • Implementation instructions
  • Tool procedures
  • Publishing, merging, or deployment
  • Completion and stop conditions

Do not flatten thinking before the decision exists.

An executable contract has explicit boundaries

A high-risk instruction identifies:

GOAL
the observable outcome
SCOPE
where the agent may act
DECISION OWNER
human, agent, or existing contract
MUST / MUST NOT
requirements and prohibitions
STOP CONDITIONS
when execution must pause
DONE WHEN
objective completion evidence

Unknowns remain visible

KNOWN
Supported by available evidence.
UNKNOWN
Required information is missing.
ASSUMPTION
Temporary; safe to use explicitly.

An UNKNOWN must not become an assumption merely to keep moving.

The combined operating loop

  1. Define the destination.
  2. Expose the current decision frontier.
  3. Explore one material question.
  4. Stop at the human gate.
  5. Record the approved decision.
  6. Compile execution into ATE.
  7. Execute and verify.
  8. Return evidence to the map.

Wayfinder governs direction. ATE governs action.

How we applied it to the NeoBank HLD

The workflow resolved, among others:

  • Consistency and freshness contracts
  • CBS and ODS authority boundaries
  • API and event contracts
  • Eight end-to-end journeys
  • Availability and recovery classes
  • Security and release controls
  • Sizing, cost, and delivery estimates
  • Agentic-engineering bootstrap cost

Each section inherited previously approved decisions.

The issue tracker became decision memory

The durable evidence included:

  • One canonical Wayfinder map
  • One ticket per material decision
  • Explicit human-gate comments
  • Stable decision summaries
  • Linked dependencies and assumptions
  • QA and merge receipts
  • A traceable route from question to final HLD

Chat supported the work; issues preserved the contract.

The workflow also exposed its own failure mode

What went wrong

Some Wayfinder scaffolding leaked into the final document:

  • Human-gate labels
  • Issue-comment headings
  • Approval language
  • Working-file notes

What we learned

Process evidence belongs in the issue tracker — not in the submission artifact.

An auditable workflow still needs a clean boundary between decision evidence and audience-facing deliverables.

Human authority, adaptable planning, precise execution

Wayfinder keeps the route honest.
Agent Technical English keeps each step precise.
The human keeps decision authority.

Use the method when

  • The destination spans multiple sessions.
  • Decisions depend on earlier decisions.
  • Agents can change external state.
  • The cost of an implicit assumption is high.

Do not use it when

One clear, reversible task is enough.
